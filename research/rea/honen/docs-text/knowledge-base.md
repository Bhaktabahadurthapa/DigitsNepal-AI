# Knowledge Base

A workspace knowledge base holds the approved material an organization teaches from:
policies, standard operating procedures, manuals, product documentation, codebooks.
It supports learning, publishing, and approved AI assistance from the same sources.

## Parallel training

The same approved material trains the humans and answers the machines:

- **People** learn it as structured courses, with progress, assessment and
  certificates.
- **Agents** answer from it on Slack, Microsoft Teams, iMessage and your own website.
  See [Agents](https://honen.com/llms/agents.md).
- **Your own AI tools** reach it over MCP, so Claude, Cursor and internal bots work
  from the same current material.

Connected sources keep the Knowledge Base current. Authors review and apply course revisions when the source material changes.

## What it holds

Documents and folders with tags, versioning and full revision history, plus images
that are searchable alongside text. Documents can be shared to the whole workspace, to
groups, to named users, or through public links. Roles run from viewer through editor
and maintainer to admin.

Screen recordings can be imported and turned into structured visual walkthroughs.

## Feeding courses

Knowledge base documents can be pulled directly into course creation, where they are
snapshotted into the course. When the original document later changes, the course
raises an alert with one-click refresh, so a course never silently drifts from the
policy it was built on.

Readings grounded in knowledge base sources carry inline citations back to the
document, with visibility configured per course. See
[the learner experience](https://honen.com/llms/learner-experience.md).

## Integrations and MCP

Content comes in from files, URLs, YouTube, public GitHub repositories, Granola meeting
notes, and connected MCP servers including Linear, Notion, HubSpot and Google Drive.

Honen also exposes its own MCP interface, so an organization's existing AI tooling can
read and write the knowledge base, read and edit courses, and drive workspace
operations under the same permissions a person would have.

## Connected sources and document versions

Native source connections include Google Drive, OneDrive, SharePoint, Notion, Confluence, Salesforce Knowledge, Document360, GitHub Documentation, and Granola. Website crawling and YouTube transcripts also bring material into the Knowledge Base. Sync scope and supported content depend on the source.

GitHub Documentation sync imports selected repository folders, Markdown, and images. Document history preserves versions and lets authors compare changes. Updated source material can inform course revisions; authors review and apply those revisions in the course editor.

## Publishing documentation

Publish Knowledge Base folders on a Site alongside courses and curricula. Choose public or restricted access, edit pages and navigation with AI, and review a live preview before publishing.

## Templates and recurring maintenance

Templates can reference Knowledge Base folders so creators begin with relevant sources. They do not grant access: the creator must already be able to use the selected folders and Skills. Readings and lecture slides can reuse original source screenshots alongside cited source text.

Agents can use approved knowledge to identify outdated courses and, with proposal permission, prepare changes for human review. Schedule those tasks through [Automations](https://honen.com/llms/automations.md). Source sync alone does not approve or publish a course update.

## Choose video import processing

Uploaded videos offer Standard and Advanced processing. Standard produces a transcript. Advanced adds relevant screenshots to the notes.
Wait for visual processing to finish, then compare the notes and screenshots with the recording before using the document as a source.
